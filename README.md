# Codex Supervisor ⭐️

写这个 Skill 的理由很简单：**我想偷懒。**

几个 Codex 窗口一起干活，本来应该更省心。结果有时我成了最忙的那个：找窗口、转述问题、催进度，再告诉新窗口“我们刚才做到哪了”。

所以有了这个小总管：让一个主窗口负责协调、检查交付和接班，把这些跑腿工作尽量交还给 Codex。人只在真正需要判断或授权的时候出场。

An instruction-only Codex Skill for coordinating independent tasks and handing work over between chats—with less window hopping and message forwarding.

## 它负责什么

- 从项目已有记录找到任务、执行者和当前进度。
- 在获授权的范围内派工、收结果、处理普通返工。
- 看实际产物再验收，不把“我做好了”直接当作完成。
- 换主窗口时交清身份、权限、进度和未完成工作，尽量复用原执行者。
- 留下一份能接着用的项目记录，最后明确停下来。

需要写文件的执行者先只读准备、确认范围并停下，主窗口核实后再单独放行。装上 Skill 不会自动扩大权限。

## 小事就别开大会了

改一句话、查一个状态，直接做就好。能在当前任务里完成的并行工作，优先考虑获授权的任务内子 agent。

只有确实需要独立窗口、跨会话续做或主窗口交接时，才用这套流程。**并行本身不是多开聊天的理由。** 总管的目标是让人省事，不是把每件小事都组织成一个项目部。

## 名字为什么长这样

默认命名大概是：

```text
⭐️ 1.10.15 [A0] 示例项目
2.10.15 [A1] 示例项目·资料整理
3.10.15 [A2] 示例项目·结果检查
```

这套编号是**我自己的使用习惯**，不是 Codex 官方规范，也不用照单全收。你已有顺手的命名方式，就按你的来。

- 前面是项目里的窗口序号和创建月日。
- `A` 表示同一组任务，后面的数字记录成员身份；换了负责人也不重编号。
- `⭐️` 放在最开头，跟着当前主窗口走。事情做完后，停在最后一个主窗口，免得下次连“该找谁”都要重新调查。

标题方便认路，真正判断身份和权限仍然要看任务 ID 与记录。

## 分区归位有一点小脾气

自用时遇到过 Codex 原生分区的回读小问题：移动工具说成功了，后续读到的项目或分区信息却可能为空或不一致。这里记录的是遇到过的表现，不代表每个版本都会复现，也不把成功回执当成界面归属已经核实。

总管会尝试归位、读回检查；只有有依据时才重试一次。还没对上，就在最后的简报里说明，必要时人手动拖一下。**不会为了摆好侧栏，把已经可以安全继续的任务卡住。** 身份、授权和实际写入范围依然要核实，不能拿这个兜底略过。

## 怎么用

先看看 [`skills/codex-supervisor/`](skills/codex-supervisor/)。想安装时，可以把下面这句话交给带有系统 `skill-installer` 的 Codex：

> 使用 skill-installer，从 grayair1021-zym/codex-supervisor 的 skills/codex-supervisor 路径安装这个 Skill；如果已有同名版本，先比较，不覆盖。

安装后可在新的任务中显式使用 `$codex-supervisor`，也可以自然地说：

> 帮我协调这个项目里已有的几个独立 Codex 任务，检查交付，真正需要我决定的事情再找我。

> 接管这个项目未完成的工作，先从项目记录核实当前负责人、授权和进度，再决定怎么继续。

创建独立聊天仍需用户明确授权。已有项目记录优先复用；没有记录时，在项目原有入口留一份即可，不需要额外数据库。

## 适用环境与边界

它依赖当前 Codex 环境提供的原生独立任务工具，例如创建、读取、联系和等待任务；只支持任务内子 agent 的环境，不一定能完成独立窗口交接。缺少所需工具时，应说明受影响的步骤，不能假装执行成功。

这是一份 Skill 指令，不是常驻进程、权限沙箱或原子锁。它不能保证后台自动唤醒、强制中断正在运行的命令，也不能靠一份 Markdown 消除所有并发冲突。没有附带 MCP、后台服务、第三方 Agent 框架或自动安装脚本。

`engineering-workflow` 是可选协作 Skill；没有安装它时，使用你项目自己的工程和验证规则。无需采用作者的记忆系统或本机发布机制。模型选择也以你的环境、偏好和授权为准。

## 验证到哪了

自用 V0 已验证过实际任务协调与接班、只读准备后单独放行的可恢复小文件操作，以及安装后的三个全新上下文：独立任务接管能自动加载，普通单项不误触发，简单并行使用任务内子 agent。

公开版在此基础上只做必要适配：将协作 Skill 改为可选、解释个人命名习惯、去掉特定笔记软件措辞，并说明缺少原生工具时的边界。公开包另行检查格式、引用、内容范围和私人信息；上述自用测试不等于公开包在所有客户端、模型或版本上的完整复测。

真实使用遇到问题再修。没有问题，就让它安静干活，大家一起偷懒。
